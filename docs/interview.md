# Agent Interview Notes

## Q0-1：Prompt是什么？你在项目中怎么用的？

**回答（1分钟版本）：**

“Prompt是输入给大语言模型的指令文本，用来引导模型完成特定任务。它的核心作用是在推理阶段控制模型的行为和输出，而不用重新训练模型。

在TripMate项目中，我设计了System Prompt，把模型固定为‘资深旅行规划助手’的角色，同时明确输出格式——包括每日行程、美食推荐、交通建议、预算估算。如果用户信息不足，Prompt里要求模型主动追问而不是编造。这就是典型的Prompt Engineering实践。

好的Prompt = 角色 + 任务目标 + 输出格式约束 + 边界行为（比如不确定时怎么办）。”


## Q0-2：System Message和User Message有什么区别？为什么重要？

**回答（1分钟版本）：**

“在调用LLM API时，Messages数组至少包含两种角色：

System Message：设置模型的底层行为规则，相当于给模型一个‘人设’和‘操作手册’，在整个对话中持续生效。User Message：用户每次提出的具体需求或问题，是模型当前要响应的内容。

两者的核心区别是稳定性和变化性——System是固定不变的底座，User是每次不同的输入。

在TripMate项目中，System Prompt定义‘你是旅行助手，输出包含行程、美食、交通、预算’，这部分对话开始后就不再变动；User Message则是用户每次输入的目的地、天数、预算，动态变化。

这个设计还有一个好处：后续做多轮对话时，System始终保持模型的行为边界，不会因为上下文变长而‘角色漂移’。”


## Q0-3：Embedding是什么？在Agent项目中有什么用？

**回答（1分钟版本）：**

“Embedding是将文本转换为高维浮点数向量的技术，使得语义相近的文本在向量空间中距离更近。同一个词在不同语境下的向量会不同，这是它与传统词向量的关键区别。

在Agent项目里，Embedding最核心的用途是RAG检索。具体流程是：

1. 把旅游攻略文档切分成片段，每个片段通过Embedding模型转成向量，存入向量数据库
2. 用户提问时，同样把问题转成向量
3. 在向量库里做余弦相似度检索，找到语义最相关的3-5个文档片段
4. 把这些片段拼接到Prompt里，让LLM基于真实资料回答

这样就把‘闭卷考试’变成了‘开卷考试’，大幅降低幻觉。

常用的Embedding模型有OpenAI的text-embedding-3-small、BGE、智谱的Embedding系列。在TripMate项目中我选了BGE，因为它在中文语义检索上表现好，而且开源可本地部署。”


## Q0-4：LLM API调用和本地部署怎么选？你的项目为什么选API？

**回答（1分钟版本）：**

“我这样选：从三个维度权衡——成本、数据安全、灵活性。

API调用的优势是零硬件成本、按token付费、能直接用最新最强的模型（比如GPT-4或DeepSeek），适合个人项目和快速验证。劣势是数据要上传第三方，隐私可控性差，长文本场景成本会累积。

本地部署的优势是数据完全在内网、长期使用成本可控、延迟更低。劣势是需要GPU服务器（至少A100或4090级别），前期投入数万到数十万，运维复杂，模型能力限于开源模型。

在TripMate项目中我选择DeepSeek API，原因有三：第一，项目处于MVP验证阶段，我要快速迭代产品形态；第二，DeepSeek中文能力强、成本低；第三，求职项目需要展示‘能调用真实API做出可运行产品’的工程能力，而不是纯理论研究。

如果未来做企业级部署，或者处理用户隐私数据，我会考虑切换为本地Qwen或Llama部署，架构上保持API可插拔。”

## Q0-5：你的项目如何保证LLM输出可靠？

“大模型输出具有一定随机性，因此项目中没有直接使用原始文本，而是要求模型按照JSON Schema生成结构化结果，并通过Pydantic进行数据验证，保证输出满足后端接口要求。”

## Q0-6：Agent和普通LLM应用有什么区别？

回答：

普通LLM应用：
用户输入 → LLM → 输出

Agent：
用户目标 → LLM规划 → Tool调用 → 环境反馈 → 下一步行动

核心区别：
LLM应用主要生成内容，
Agent主要完成任务。

## Q0-7：为什么你的项目需要Agent？
回答：

旅行规划不仅需要生成文本，还涉及实时天气、交通、景区信息等动态数据。传统LLM只能依靠参数记忆生成内容，而Agent可以根据任务需求主动调用外部工具获取信息，再结合LLM完成规划。

## Q1：为什么LLM可以生成文本？
面试高频追问序列
### Q1.1：LLM生成文本的底层原理是什么？

“本质是自回归式条件语言建模。模型学习的是概率分布P(wi | w1, w2, ..., wi-1)，也就是给定前文，预测下一个词的概率。训练时用海量文本做无监督学习，通过交叉熵损失最大化正确token的预测概率。生成时，每预测出一个新token就拼回输入，重复这个过程直到产出<eos>或达到最大长度。整个过程没有‘理解’和‘规划’，纯粹是条件概率的链式乘积。”

### Q1.2：Softmax在这里起什么作用？

“模型最后一层输出的隐状态向量是任意实数（logits），Softmax把它映射成词表上和为1的概率分布。公式是p_i = e^{z_i} / Σe^{z_j}。它放大了最大值和次大值之间的差距，让概率分布更尖锐，便于采样。温度参数T就是在Softmax之前除以T：T<1让分布更尖锐（倾向选最大概率），T>1让分布更平滑（增加随机性）。”

### Q1.3：Temperature=0和Temperature=1有什么区别？实际怎么设？

“T=0叫贪心解码（greedy），永远选概率最高的token，结果是确定性的，但容易陷入重复循环。T=1保持原始概率分布。实际中很少用0，因为缺乏多样性；也很少用1，因为太随机。通常设0.7-0.9平衡质量和多样性。要注意T=0不是概率为1，而是argmax，相当于把100%概率给最高项——严格说温度趋近0才是贪心，代码实现里T=0直接走argmax分支。”

### Q1.4：什么是Top-p采样？为什么比Top-k好？

“Top-p（核采样）是动态截断：按概率从高到低累加，直到累计概率达到p（如0.9），只在这个集合内采样。好处是自适应——概率分布集中时截断少（保留确定性），分散时截断多（过滤长尾噪声）。Top-k是固定截断前k个，但k不好调：分布平坦时k=50可能漏掉合理词，分布尖锐时k=50又塞进一堆低概率噪声。实践中Top-p + 温度联合调节是主流。”

### Q1.5：LLM是“理解”了文本还是“记住”了文本？

“严格说两者都不是。它学的是高维空间中的统计关联——哪些词在哪些语境下共现。比如它知道‘苹果’和‘手机’在科技语境下共现，是因为训练数据里这些模式出现了亿万次。这不是人类意义上的‘理解’，也不是SQL式的‘记忆’，而是通过神经网络的分布式表征压缩了整个语料的统计规律。这也是为什么它能做推理（模式泛化）但也会产生事实性错误——因为它没区分过‘真实’和‘虚构’文本的区别。”

### 完整知识面
| 知识点 | 掌握程度 | 补充说明 |
|---|---|---|
| 自回归 vs 自编码 | 必会 | GPT是自回归（单向），BERT是自编码（双向） |
| 语言模型目标函数 | 必会 | 交叉熵损失 = -Σlog P(wi\|context) |
| 采样策略 | 必会 | Greedy / Beam Search / Top-k / Top-p / Temperature |
| 困惑度（Perplexity） | 了解 | 2^{交叉熵}，衡量模型对序列的“惊讶程度” |
| 因果掩码（Causal Mask） | 必会 | 防止训练时看到未来token，下三角掩码 |
| LLM的“理解”本质 | 加分 | 分布式表征+统计关联，不是符号逻辑 |


## Q2：Transformer为什么适合LLM？
面试高频追问序列
### Q2.1：Transformer的核心机制是什么？

“核心是多头自注意力（Multi-Head Self-Attention）。输入序列每个位置生成Q、K、V三个向量，用Q和所有K做点积算相似度，经Softmax得到注意力权重，再加权求和所有V，得到该位置的上下文感知表征。多头就是多组QKV投影矩阵并行计算，让模型从不同子空间捕捉不同关系（如语法、语义、指代）。然后叠上残差连接和LayerNorm，再加FFN前馈网络——这就是Transformer Block。”

### Q2.2：Self-Attention相比RNN的优势在哪？

“三个核心优势：第一，长距离依赖。RNN信息要逐时间步传递，距离远时梯度消失或衰减，而Self-Attention任意两位置直接计算内积，距离对信息流动无影响。第二，并行训练。RNN依赖t-1时刻的输出，天然串行；而Attention矩阵一次性算所有两两关系，整序列并行送入GPU矩阵乘。第三，可解释性。注意力权重可视化出来能看到模型‘关注’哪些位置。”

### Q2.3：为什么Transformer能扩展到千亿参数？

“架构设计上保证了堆叠稳定性：残差连接（Residual Connection）让梯度能直接流回浅层，避免梯度消失；LayerNorm在每一层稳定激活值分布，防止内部协变量偏移。工程上Self-Attention的矩阵乘法是GPU友好的密集运算，算力利用率高。而且Attention没有强加归纳偏置（比如CNN假设局部性），模型容量完全由数据驱动，数据够多时参数越多上限越高——这就是Scaling Law的实证结论。”

### Q2.4：Transformer的复杂度O(n²)怎么理解？这是优势还是劣势？

“O(n²)是指计算复杂度随序列长度平方增长——每个位置要和所有位置算注意力。训练时这是可接受的（n=2048），甚至是个优势（全局视野）。但推理和长文本是灾难：生成时n每增加1，计算量增加n。这也是为什么GPT-4等模型有上下文窗口限制。工业界应对方案有：稀疏Attention（只算局部窗口+全局token）、线性Attention（O(n)）、以及Mamba等状态空间模型——它们试图在保持长程能力的同时降低复杂度。”

### Q2.5：为什么现在有些研究在“摆脱Transformer”？

“O(n²)在长序列上逐渐成为天花板，而且Attention的‘全局交互’在超长上下文（如100万token）中大部分计算其实是冗余的——模型不需要看每一个token。Mamba这类选择性状态空间模型用O(n)复杂度同时保持线性记忆，在某些长序列任务上性能匹敌或超过Transformer。但Transformer的生态优势（硬件优化、预训练权重、社区工具）太强，短期内不会被完全替代，更多是融合思路（如Transformer + Mamba混合架构）。”

### 完整知识面
| 知识点 | 掌握程度 | 补充说明 |
|---|---|---|
| Self-Attention公式 | 必会 | Attention(Q,K,V)=softmax(QK^T/√d_k)V |
| Multi-Head | 必会 | 多头拼接后投影，头数通常8-96 |
| 位置编码 | 必会 | Sin/Cos绝对位置或RoPE相对位置 |
| 残差连接+LayerNorm | 必会 | Pre-Norm架构更稳定（GPT用了Post-Norm变体） |
| FFN（前馈网络） | 必会 | 两层线性+GELU激活，参数占比2/3 |
| O(n²)复杂度 | 必会 | 计算和内存都随序列长度平方增长 |
| KV Cache | 加分 | 推理时缓存已生成的K、V，避免重复计算 |
| Mamba / 线性Attention | 加分 | 了解为何要替代Transformer及局限 |



## Q3：Token和字符有什么区别？
面试高频追问序列
### Q3.1：什么是Token？和字符什么关系？

“字符是书写系统的原子单位（'a'、'中'），Token是模型词表的原子项，是模型能直接处理的最小语义单元。Tokenizer把原始字符串映射成整数ID列表，模型只认这些ID。Token可以是完整词、词根、子词或单个字符——取决于词表设计和分词算法。关系是：字符经过分词算法聚合/拆分后变成Token，所以Token比字符粒度更粗，但也比单词更灵活。”

### Q3.2：BPE具体怎么工作？

“BPE（Byte-Pair Encoding）是自底向上的迭代合并算法。步骤：先把所有文本拆成字节或字符级别，统计所有相邻符号对的频次，找到最高频的那一对合并成新符号，加入词表；重复这个过程直到词表达到预设大小（如32k或100k）。所以词表里既有高频词（'the'），也有词根（'un'、'ing'），还有单个字符（'z'）。训练阶段只做合并统计，推理时直接用学到的合并规则切分新文本——最长匹配原则。”

### Q3.3：中文文本的Tokenization有什么特殊之处？

“中文没有自然空格分割，所以BPE的训练语料中中文字符的共现统计和英文不同。主流做法是Byte-level BPE：先把中文字符编码成UTF-8的1-3个字节，然后在这些字节序列上做合并。结果是：常用汉字（'我'、'你'）在语料中高频出现，可能合并成单个Token；生僻汉字（'爨'）罕见，可能拆成多个字节Token。但整体上中文同语义文本的Token数比英文多30%-50%，因为中文信息熵高但词表切分效率不如英文。”

### Q3.4：词表大小怎么权衡？大会怎样？小会怎样？

“词表大：每个Token含更多信息（序列更短→Attention更快），但Embedding层参数量大（词表大小×嵌入维度），训练和存储成本增加，且罕见token缺乏训练数据学习不好。词表小：Embedding层参数少，但序列更长导致Attention O(n²)暴涨，且细粒度切分（如单字符）丢失语义信息。主流平衡在32k-100k，GPT-4约100k，Llama 32k。工程上还考虑多语言覆盖率——词表大对非英语更友好。”

### Q3.5：实际开发中Token限制要注意什么？

“第一计费：OpenAI按Token计费，输入输出都算。第二上下文窗口：模型说8K是指Token数，不是字符数或字数。中文场景下你估1汉字≈1.5Token、1英文单词≈1.3Token快速估算。第三截断风险：超长输入会被截断或报错，需要在调用前做Token计数（用tiktoken库）。第四成本优化：System Prompt和少样本示例也占Token，尽量精简。面试时提到‘中文同语义下比英文多30-50% Token’是加分项。”

### 完整知识面
| 知识点 | 掌握程度 | 补充说明 |
|---|---|---|
| BPE算法 | 必会 | 迭代合并高频对，核心是统计+贪心 |
| WordPiece | 了解 | BERT用，基于似然增加而非频次 |
| SentencePiece | 了解 | 直接处理原始文本，无需预分词，适合多语言 |
| Unigram | 了解 | T5用，基于概率模型删除低质量token |
| 词表大小权衡 | 必会 | Embedding参数量 = vocab_size × hidden_size |
| UTF-8编码 | 了解 | 中文1字=3字节，BPE在字节级操作 |
| tiktoken | 加分 | OpenAI官方Token计数工具 |
| 中英文Token差异 | 加分 | 中文更费Token，面试被问概率极高 |

## Q4：LLM为什么会幻觉？
面试高频追问序列
### Q4.1：幻觉的根本原因是什么？

“根本原因是优化目标和真实需求不一致。LLM的训练目标是最大化训练数据上的似然概率——也就是学会预测‘人类在给定上文时最可能写什么’。它不区分这段文本是维基百科事实还是网络小说虚构。所以当Prompt处于模型知识的模糊区域时（记忆不精确或没有相关数据），它会选择概率最高的‘流畅补全’，而这个补全可能是错的。换句话说，模型没有内置的‘事实检查’或‘不确定信号’——它被迫要吐出一个词，不能回答‘我不知道’。”

### Q4.2：幻觉有哪些类型？

“学术界通常分三类：第一，输入冲突型——用户提供的信息和模型记忆矛盾时，模型有时会忽略用户输入而依赖自己的参数化记忆。第二，事实冲突型——模型生成的内容和公认事实不符，如编造历史人物生卒年。第三，上下文冲突型——模型在生成长文本时忘记自己前面写过什么，导致前后矛盾。前两种是知识问题，后一种是长程一致性问题。”

### Q4.3：RAG为什么能缓解幻觉？原理是什么？

“RAG（检索增强生成）在生成前先做一步外部知识检索，把检索到的相关文档拼接到Prompt的上下文里，让模型基于检索结果生成而不是靠内部记忆。本质是把‘闭卷考试’变成‘开卷考试’。为什么有效：检索结果提供了具体的事实锚点，模型在生成时Attention会分配到这些文档上，增加了正确事实被选中的概率。但RAG不能完全消除幻觉——如果检索到的文档本身就是错的，或者模型在综合多个文档时做了错误归纳，依然会生成错误内容。”

### Q4.4：Tool Calling对幻觉的帮助是什么？

“Tool Calling让模型在需要精确信息时不靠记忆生成，而是调用外部工具获取真实数据。比如‘今天的天气’调用天气API，‘127×311等于多少’调用计算器。这样模型把容易出错的模块外包给确定性系统。但前提是模型要能准确判断‘什么时候该调用工具’以及‘调用哪个工具’——这两步本身也可能出错。所以Tool Calling是转移风险，不是消除风险。”

### Q4.5：幻觉能彻底消除吗？

“从理论上看不能。因为LLM本质是概率模型，任何概率采样都有机会跳出‘事实正确’的路径。即使温度设0取argmax，如果错误token的概率最高（比如训练数据里错误表述更多），依然会输出幻觉。工程上我们能做的是降低幻觉概率到可接受水平——通过RAG提供事实锚点、通过RLHF让模型更倾向拒答不确定问题、通过指令微调让模型学会说‘我不知道’。但绝对零幻觉在统计生成模型上是不可能的。”

### Q4.6：实际项目中怎么系统应对幻觉？

“三层防线：第一层——训练/微调阶段：在SFT数据中加入拒答样本（‘我不知道’），用RLHF偏好数据惩罚编造行为。第二层——推理阶段：用RAG检索外部知识；对数学/时间敏感问题强制走Tool Calling；设置系统Prompt强调事实性。第三层——后处理：生成后做事实一致性检查（如用另一个模型评估），或把答案中的事实性陈述单独提取出来做二次检索验证。面试时能分这三层说明有实战经验。”

## Q5：什么是Agent？
面试高频追问序列
### Q5.1：Agent和ChatGPT的核心区别是什么？

“核心区别是范式不同。ChatGPT是问答范式：用户输入→模型前向传播→输出结果，一次完成，无状态。Agent是决策范式：用户给一个目标（不是单轮指令），模型进入一个循环——思考当前状态、决定下一步行动、调用工具执行、观察结果、再思考...直到目标达成或达到终止条件。简单说：ChatGPT是‘回答问题’，Agent是‘完成任务’。Agent的架构是：LLM作为大脑 + 规划模块 + 工具库 + 记忆系统 + 执行监控。”

### Q5.2：Agent的规划（Planning）具体怎么实现？

“规划的核心是任务分解和动态调整。主流实现方式：CoT（思维链） 让模型一步步推理中间步骤；ReAct（Reason+Act） 交替输出‘思考’和‘行动’，让推理和外部交互交错进行；更复杂的ToT（思维树） 在每一步探索多个分支，通过搜索算法（如BFS/DFS）找到最优路径。工程上通常用Prompt工程让模型输出结构化JSON，包含‘思考’、‘下一步行动’、‘工具参数’等字段，由外部调度器解析执行。”

### Q5.3：工具调用是怎么训练出来的？

“分两个阶段。第一阶段：指令微调时加入工具调用数据——构造包含‘工具描述+用户问题+调用JSON+工具返回结果+最终回答’的样本，让模型学会按指定格式输出工具调用。第二阶段：推理时通过Prompt描述工具（名称、参数、功能），模型根据描述Zero-shot生成调用。核心是模型需要在预训练阶段见过‘API调用’、‘JSON结构’等文本格式，否则Finetune也学不会。Tool Calling本质是结构化输出生成，不是真的‘执行’工具，是由外部框架解析后执行。”

### Q5.4：Agent的记忆系统怎么设计？

“分短期记忆和长期记忆。短期记忆就是当前会话的上下文窗口——所有历史思考、行动、观察都拼在Prompt里，窗口满了需要截断或摘要压缩。长期记忆用向量数据库（如Chroma、Pinecone）存储历史交互或外部知识，需要时做语义检索，把相关记忆拼入上下文。工程挑战是记忆检索的时机（什么时候主动检索）、记忆的更新策略（怎么判断新信息重要）、以及记忆的冲突解决（旧记忆和新事实矛盾时怎么处理）。”

### Q5.5：Agent最大的技术瓶颈是什么？

“当前最大瓶颈是规划依赖的推理能力不足。LLM在多步推理中容易‘逻辑断裂’——中间一步错了后面全偏，而且没有内置的‘回溯机制’（发现错了不会自动退回重试）。另外工具调用准确率也不够——模型可能选错工具、填错参数、或忽略工具返回的关键信息。工程上的应对是：加入自我反思（Self-Reflection） 环节（每次执行后让模型评估结果是否合理）、设置检查点（关键节点人工确认）、以及多Agent协作（不同Agent承担规划/执行/验证角色相互校验）。”

### Q5.6：Agent和RAG是什么关系？

“RAG可以看作Agent的特例或子集。RAG只有‘检索工具’，Agent可能有几十种工具。RAG流程固定（检索→生成），Agent流程动态（自主决定下一步）。但从架构角度看，RAG就是Agent的一个简化版——LLM + 一个工具（检索器）+ 单步执行。Agent是RAG的泛化，RAG是Agent的最小可行实现。面试时被问‘Agent和RAG的区别’，回答‘Agent包含RAG，但扩展了规划、多工具和循环决策’是最清晰的表达。”
